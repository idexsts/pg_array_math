
<h1 align="center">pg_array_math</h1>

<p align="justify">
Расширение для PostgreSQL, реализующее поэлементные
арифметические и математические операции над одномерными числовыми массивами.
</p>

<h2 align="center">1. Описание задач</h2>

<h3>1.1. Назначение расширения</h3>

<p align="justify">
Расширение <strong>pg_array_math</strong> предназначено для выполнения математических операций над одномерными массивами в системе управления базами данных PostgreSQL. Оно предоставляет набор пользовательских функций, реализованных на языке C, которые позволяют выполнять арифметические вычисления и математические преобразования непосредственно средствами SQL.
</p>

<h3>1.2. Реализованные возможности</h3>

<p align="justify">
Расширение <strong>pg_array_math</strong> предоставляет 11 пользовательских функций для выполнения математических операций над массивами PostgreSQL. Реализованные функции можно разделить на три основные группы:
</p>
<strong>1. Арифметические операции над двумя массивами (бинарные операции):</strong>

- `array_add` — поэлементное сложение двух массивов;
- `array_sub` — поэлементное вычитание элементов второго массива из соответствующих элементов первого;
- `array_mul` — поэлементное умножение двух массивов;
- `array_div` — поэлементное деление элементов первого массива на соответствующие элементы второго.

<strong>2. Арифметические операции над массивом и числом:</strong>

- `array_add_scalar` — прибавление заданного числа к каждому элементу массива;
- `array_mul_scalar` — умножение каждого элемента массива на заданное число.

<strong>3. Математические функции:</strong>

- `array_power` — возведение каждого элемента массива в заданную степень;
- `array_sqrt` — вычисление квадратного корня каждого элемента массива;
- `array_abs` — вычисление абсолютного значения каждого элемента массива;
- `array_log` — вычисление натурального логарифма каждого элемента массива;
- `array_exp` — вычисление экспоненты каждого элемента массива.

Для выполнения вычислений поддерживаются числовые типы данных SMALLINT, INTEGER, BIGINT, REAL, DOUBLE PRECISION и NUMERIC. При этом набор поддерживаемых типов зависит от конкретной функции и характера выполняемой операции. Об этом подробнее в разделе [«2.2. Поддерживаемые типы данных»](#supported-types).



Дополнительно реализована обработка некорректных входных данных и граничных случаев, включая проверку совместимости массивов, деление на ноль, недопустимые значения для математических операций и переполнение числовых типов. Более подробно возможные ошибочные ситуации описаны в [«2.5. Обработка ошибок и граничных случаев»](#error-handling).


<h2 align="center">2. Дизайн расширения</h2>

<h3>2.1. Архитектура расширения</h3>

<p align="justify">
Архитектура расширения основана на взаимодействии SQL-интерфейса PostgreSQL и функций, реализованных на языке C. Каждая пользовательская функция объявляется в SQL-файле расширения и связывается с соответствующей функцией на C.
</p>
<p align="justify">
Для организации расширения используются следующие файлы:
</p>

- `pg_array_math.c` — исходный С-код, содержащий реализацию математических функций и вспомогательных методов;
- `pg_array_math--1.0.sql` — SQL-объявления пользовательских функций, доступных для вызова из запросов PostgreSQL;
- `pg_array_math.control` — файл с метаданными расширения, необходимыми для его установки;
- `Makefile` — настройки сборки и установки расширения.


Для взаимодействия с PostgreSQL каждая C-функция регистрируется с помощью макроса `PG_FUNCTION_INFO_V1`. Аргументы функций извлекаются средствами серверного API, а результат возвращается в формате Datum, используемом PostgreSQL для представления значений различных типов данных.


<p align="justify">
Для упрощения реализации и повторного использования кода были разработаны вспомогательные функции, отвечающие за проверку поддерживаемых типов, разбор входных массивов, создание результирующих массивов и проверку арифметического переполнения.
</p>


<a id="supported-types"></a>
<h3>2.2. Поддерживаемые типы данных</h3>

<p align="justify">
Расширение поддерживает следующие числовые типы данных PostgreSQL:
</p>

| Тип PostgreSQL | Описание |
|---|---|
| `SMALLINT` | 16-битное целое число |
| `INTEGER` | 32-битное целое число |
| `BIGINT` | 64-битное целое число |
| `REAL` | Число с плавающей точкой одинарной точности |
| `DOUBLE PRECISION` | Число с плавающей точкой двойной точности |
| `NUMERIC` | Число произвольной точности |

<p align="justify">
При работе с двумя массивами их типы элементов должны совпадать. Это обеспечивается механизмом полиморфных типов PostgreSQL: сигнатуры функций используют тип ANYARRAY, поэтому PostgreSQL проверяет совместимость типов аргументов при разрешении вызова функции. 
</p>
<p align="justify">
Для функций, принимающих один массив и возвращающих массив того же типа, также используется полиморфная сигнатура ANYARRAY → ANYARRAY. Это означает, что тип возвращаемого массива определяется типом входного массива и должен ему соответствовать. Такой подход позволяет сохранять исходный тип элементов при выполнении операций.
</p>

Данное ограничение не позволяет использовать целочисленные типы для функций `array_log` и `array_exp`. Результаты вычисления натурального логарифма и экспоненты в общем случае являются дробными числами, поэтому их невозможно корректно представить в исходном целочисленном типе без потери дробной части. Поскольку сигнатура ANYARRAY → ANYARRAY требует сохранения типа результата, для этих функций поддерживаются только REAL, DOUBLE PRECISION и NUMERIC.

<h3>2.3. Обработка массивов</h3>

Для обработки массивов используется стандартный API PostgreSQL. Поскольку внутреннее представление массива отличается от обычного C-массива, перед выполнением вычислений необходимо преобразовать его в последовательность элементов типа Datum. Для этого реализована вспомогательная функция `deconstruct_input_array`.

<p align="justify">
После разбора массива основная функция выполняет необходимые вычисления над соответствующими элементами. Для работы с различными числовыми типами используются специальные средства PostgreSQL, позволяющие преобразовывать значения Datum в соответствующие типы C.
</p>


После завершения вычислений результирующий массив формируется с помощью вспомогательной функции `construct_result_array`. Она использует механизм создания массивов PostgreSQL и учитывает тип элементов, количество значений и нижнюю границу массива.


<p align="justify">
Для непустых массивов сохраняется исходная нижняя граница индексации. Пустые массивы обрабатываются отдельно.
</p>

<p align="justify">
NULL-элементы обрабатываются отдельно от обычных значений: если элемент входного массива равен NULL, соответствующий элемент результата также будет NULL. 
</p>

<h3>2.4. Используемые алгоритмы</h3>

| Функции | Используемый алгоритм | Временная сложность |
|---|---|---|
| `array_add`, `array_sub`, `array_mul`, `array_div` | Поэлементная обработка двух массивов за один проход | O(n) |
| `array_add_scalar`, `array_mul_scalar` | Последовательный проход по массиву с выполнением операции над каждым элементом | O(n) |
| `array_power` | Быстрое возведение в степень методом бинарного разложения показателя для целочисленных типов | O(n log k) |
| `array_sqrt` | Последовательная обработка элементов; для целых чисел используется целочисленный квадратный корень | O(n) |
| `array_abs` | Последовательное вычисление абсолютного значения каждого элемента | O(n) |
| `array_log`, `array_exp` | Последовательное применение математических функций к каждому элементу | O(n) |

<p align="justify">
В таблице n обозначает количество элементов массива, а k — показатель степени. Для функции array_power сложность O(n log k) относится к обработке целочисленных массивов с использованием быстрого возведения в степень. Для вещественных типов используются стандартные математические функции.
</p>

<a id="error-handling"></a>
<h3>2.5. Обработка ошибок и граничных случаев</h3>

<p align="justify">
Реализованы следующие проверки:
</p>

- **Проверка типов данных.** Отклоняются массивы с неподдерживаемыми типами элементов;
- **Проверка размерности.** Поддерживаются только одномерные массивы;
- **Проверка количества элементов.** Для операций над двумя массивами требуется одинаковое количество элементов;
- **Деление на ноль.** При обнаружении нулевого делителя генерируется ошибка;
- **Проверка квадратного корня.** Отрицательные значения не допускаются;
- **Проверка логарифма.** Аргументы должны быть строго положительными;
- **Проверка переполнения.** Для целочисленных операций контролируется выход результата за допустимые границы типа;
- **Проверка специальных значений.** Для чисел с плавающей точкой учитываются NaN и бесконечность, а также некорректные результаты математических операций;
- **Обработка NULL.** NULL-элементы массивов сохраняются в соответствующих позициях результата.

<p align="justify">
Отдельно учитываются пустые массивы и особенности нижней границы индексации.
Также все функции расширения объявлены с атрибутом STRICT. Это означает, что если хотя бы один из аргументов функции имеет значение SQL NULL, PostgreSQL автоматически возвращает NULL, не выполняя тело функции.
</p>

<h3>2.6. Особенности реализации на языке C</h3>

<p align="justify">
Основные особенности реализации:
</p>

- **Тип `Datum`.** Используется для универсального представления значений PostgreSQL внутри C-функций.
- **Макросы `PG_GETARG_*`.** Применяются для получения и преобразования аргументов, переданных SQL-функциям.
- **OID типов данных.** Используются для определения и проверки типов элементов входных массивов.
- **Функция `deconstruct_array`.** Преобразует входной массив PostgreSQL в последовательность элементов, доступных для обработки в C.
- **Функция `construct_md_array`.** Используется для формирования результирующего массива PostgreSQL из обработанных элементов.
- **Обработка NULL.** Для хранения информации о NULL-элементах используются отдельные массивы логических признаков.
- **Макросы `PG_RETURN_*`.** Применяются для возврата результатов выполнения C-функций в PostgreSQL.
- **Механизм `ereport` и `errmsg`.** Используется для формирования и передачи сообщений об ошибках средствами PostgreSQL.
  
<h2 align="center">3. Сигнатуры функций</h2>
<p align="justify">
Все функции объявлены с атрибутами IMMUTABLE и STRICT. Атрибут IMMUTABLE
указывает, что результат функции определяется только её аргументами.
Атрибут STRICT означает, что при передаче SQL NULL хотя бы в один из
аргументов PostgreSQL автоматически возвращает NULL, не выполняя тело функции.
</p>

<a id="scenarios"></a>
<h2 align="center">4. Сценарии использования</h2>

<h3>4.1. Сложение массивов</h3>

```sql
SELECT array_add(
    ARRAY[1, 2, 3], 
    ARRAY[4, 5, 6]
);
-- Результат: {5,7,9}
```
```sql
SELECT array_add(
    ARRAY[1.5, 2.5, 3.5]::double precision[],
    ARRAY[2.0, 3.0, 4.0]::double precision[]
);
-- Результат: {3.5,5.5,7.5}
```
```sql
SELECT array_add(
    ARRAY[1, 2, 3]::integer[],
    ARRAY[4, 5]::integer[]
);
-- Ожидается: ERROR:  array lengths must match
```
<h3>4.2. Вычитание массивов</h3>

```sql
SELECT array_sub(
    ARRAY[10, 20, 30],
    ARRAY[1, 2, 3]
);
-- Результат: {9,18,27}
```
```sql
SELECT array_sub(
    ARRAY[100, 200, 300]::bigint[],
    ARRAY[10, 20, 30]::bigint[]
);
-- Результат: {90,180,270}
```
```sql
SELECT array_sub(
    ARRAY[10, 20, 30]::integer[],
    ARRAY[1, 2]::integer[]
);
-- Ожидается: ERROR:  array lengths must match
```
<h3>4.3. Умножение массивов</h3>

```sql
SELECT array_mul(
    ARRAY[2, 3, 4]::integer[],
    ARRAY[5, 6, 7]::integer[]
);
-- Результат: {10,18,28}
```
```sql
SELECT array_mul(
    ARRAY[1.5, 2.5, 3.5]::numeric[],
    ARRAY[2, 3, 4]::numeric[]
);
-- Результат: {3.0,7.5,14.0}
```
```sql
SELECT array_mul(
    ARRAY[2147483647, 2]::integer[],
    ARRAY[2, 3]::integer[]
);
-- Ожидается ошибка: ERROR:  integer multiplication overflow
```

<h3>4.4. Деление массивов</h3>

```sql
SELECT array_div(
    ARRAY[10.0, 20.0, 30.0]::double precision[],
    ARRAY[2.0, 4.0, 5.0]::double precision[]
);
-- Результат: {5,5,6}
```
```sql
SELECT array_div(
    ARRAY[10, 15, 20]::numeric[],
    ARRAY[2, 3, 4]::numeric[]
);
-- Результат: {5.0000000000000000,5.0000000000000000,5.0000000000000000}
```
```sql
SELECT array_div(
    ARRAY[10, 20, 30]::integer[],
    ARRAY[2, 0, 5]::integer[]
);
-- Ожидается: ERROR:  integer division by zero
```

<h3>4.5. Арифметические операции с числом</h3>

```sql
SELECT array_add_scalar(
    ARRAY[1, 2, 3]::integer[],
    10::integer
);
-- Результат: {11,12,13}
```
```sql
SELECT array_mul_scalar(
    ARRAY[1.5, 2.5, 3.5]::double precision[],
    2.0::double precision
);
-- Результат: {3,5,7}
```
```sql
SELECT array_add_scalar(
    ARRAY[2147483647]::integer[],
    1::integer
);
-- Ожидается: ERROR:  integer addition overflow
```
<h3>4.6. Возведение элементов массива в степень</h3>

```sql
postgres=# SELECT array_power(
    ARRAY[2.0, 3.0, 4.0]::double precision[],
    0.5::numeric
);
-- Результат:  {1.4142135623730951,1.7320508075688772,2}
```
```sql
SELECT array_power(
    ARRAY[100000]::integer[],
    3::numeric
);
-- Ожидается: ERROR:  integer power overflow
```

<h3>4.7. Вычисление квадратного корня</h3>

```sql
SELECT array_sqrt(
    ARRAY[4, 9, 16, 25]::bigint[]
);
-- Результат: {2,3,4,5}
```
```sql
SELECT array_sqrt(
    ARRAY[4, -9, 16]::integer[]
);
-- Ожидается: ERROR:  cannot take square root of a negative number
```

<h3>4.8. Вычисление модуля</h3>

```sql
SELECT array_abs(
    ARRAY[-1.5, -2.75, 3.5]::numeric[]
);
-- Результат: {1.5,2.75,3.5}
```
```sql
SELECT array_abs(
    ARRAY[-2147483648]::integer[]
);
-- Ожидается: ERROR:  integer absolute value overflow
```

<h3>4.9. Вычисление логарифма</h3>

```sql
SELECT array_log(
    ARRAY[1.0, 2.7182817, 7.389056]::real[]
);
-- Результат: {0,0.99999994,2}
```
```sql
SELECT array_log(
    ARRAY[1.0, 0.0, 2.0]::double precision[]
);
-- Ожидается: ERROR:  natural logarithm is defined only for positive numbers
```

<h3>4.10. Вычисление экспоненты</h3>

```sql
SELECT array_exp(
    ARRAY[0, 1, 2]::numeric[]
);
-- Результат: {1.0000000000000000,2.7182818284590452,7.3890560989306502}
```
```sql
SELECT array_exp(
    ARRAY[10000.0]::double precision[]
);
-- Ожидается: ERROR:  double precision exponential overflow
```

<h2 align="center">6. Установка и сборка</h2>


<h3>6.1. Сборка и установка через PGXS</h3>

Для сборки расширения отдельно от исходного дерева PostgreSQL используется PGXS (PostgreSQL Extension Building Infrastructure).

Перейдите в каталог расширения:

```bash
cd ~/.../pg_array_math
```

Выполните сборку:

```bash
make USE_PGXS=1
```

Установите расширение:

```bash
make USE_PGXS=1 install
```

При необходимости для установки в системные каталоги могут потребоваться права администратора.

<h3>6.2. Интеграция в каталог contrib PostgreSQL</h3>

Для интеграции расширения в исходное дерево PostgreSQL необходимо разместить его в каталоге `contrib`.

Скопируйте каталог расширения в `contrib`. 
Добавьте `pg_array_math` в список `SUBDIRS` файла `contrib/Makefile`.

Перейдите в корневой каталог исходного дерева PostgreSQL и выполните сборку: 
```bash
make -C contrib/pg_array_math
```
Установите расширение:
```bash
make -C contrib/pg_array_math install
```
Для проверки установки выполните:
```bash
make -C contrib/pg_array_math installcheck
```

<h3>6.3. Подключение расширения к базе данных</h3>

После сборки и установки расширение можно подключить к выбранной базе данных PostgreSQL.

Подключитесь к базе данных:

```bash
psql -d postgres
```

Создайте расширение:

```sql
CREATE EXTENSION pg_array_math;
```

Для проверки наличия установленного расширения выполните:

```sql
SELECT *
FROM pg_extension
WHERE extname = 'pg_array_math';
```

<h3>6.4. Проверка работы расширения</h3>

После подключения расширения можно проверить работу реализованных функций с помощью SQL-запросов. См. [«4. Сценарии использования»](#scenarios).
